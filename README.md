# World of Vibecraft

[Сайт студии](https://rinpocheshka.github.io/wov/) · [BriefOps](https://github.com/Rinpocheshka/briefops)

Лендинг услуг веб-разработки и автоматизации: первая версия MVP, перенос дизайна в код и интеграция ИИ в бизнес-процессы. Объём, сроки, стоимость и требования к эксплуатации согласуются по конкретной задаче.

## Устройство сайта

Статические HTML, CSS и JavaScript, без сборки и внешних CDN. Размещение — GitHub Pages. Указанные на странице Next.js, Supabase и другие технологии — возможные инструменты клиентских проектов; сам лендинг их не использует.

- `index.html` — содержание, доступные подписи полей и нативная форма.
- `styles.css` — адаптивные стили, светлая/тёмная темы и уменьшение анимации по системной настройке.
- `app.js` — интерфейс, тема и отправка формы.
- `wov.png` — логотип.

## Заявки

Форма отправляет имя, email или Telegram-контакт и описание задачи прямо в `https://briefops.onrender.com/api/integrations/wov`. BriefOps сначала сохраняет заявку в отдельной закрытой базе и ставит уведомление владельцу в постоянную очередь. Вся почта владельца не импортируется и не читается.

Успех показывается только после подтверждения сервера. При ошибке заполненные поля остаются на странице. Повтор неизменённой заявки использует тот же `submission_id`; изменение данных создаёт новый ID. Контактные данные не сохраняются в localStorage. При выключенном JavaScript работает нативная отправка формы с серверной страницей подтверждения.

Ответ клиенту отправляется из закрытого кабинета BriefOps после согласования и отдельного нажатия кнопки отправки. Если клиент оставил только Telegram, автоматического сообщения в мессенджер нет. Ответы на email остаются в Gmail.

## Проверка и ограничения

```bash
node --check app.js
python -m http.server 8000
```

Локально можно проверять внешний вид и валидацию. Production API разрешает Origin `https://rinpocheshka.github.io`: локальная отправка намеренно отклоняется. Для интеграционных проверок нужен изолированный сервер BriefOps с тестовым адаптером почты.

Скрипты и стили вынесены в отдельные файлы: CSP не требует `unsafe-inline`. Проверка полей в браузере помогает пользователю, а не заменяет серверную проверку. Ограничения Origin/CORS и ловушка не являются криптографической проверкой происхождения: публичная форма потенциально требует усиления антиспамом при росте нагрузки. GitHub Pages не поддерживает произвольные заголовки защиты от iframe.

Подробности серверной проверки и известных ограничений — [AUDIT.md](https://github.com/Rinpocheshka/briefops/blob/main/AUDIT.md).
